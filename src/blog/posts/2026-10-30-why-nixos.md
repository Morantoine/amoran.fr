title: What NixOS lets me do
description: A laptop that wipes itself on boot, a server with fifty services, and why I keep putting up with Nix.

Every time my laptop boots, it deletes `/` and my home directory and starts from an empty
snapshot. Firefox profile, shell history, SSH keys, the handful of folders I care about: those
come back, because I listed them somewhere. Everything else is gone. The `.cache` junk, the config
file some tool dropped in `~` six months ago, the package I installed "just to test". Gone.

I'd never have tried this on Arch. On NixOS it took an afternoon, and it's a good way to explain
why I use it.

## The machine is the repo

I have three machines. balrog is my laptop, cyboogie is a server that runs pretty much my whole
digital life (photos, passwords, mail, music, my Git forge, around fifty services), and gila is a
tiny VPS whose only job is to watch cyboogie and yell at my phone when it goes down.

All three come from one Git repo. Not "the repo has my dotfiles and a setup script": the repo
*is* the machines. If something isn't in there, it doesn't exist on any of them, and the next
rebuild will make sure of it. That's also why the wipe-on-boot thing works. The system gets
rebuilt from the description anyway, so the only things worth keeping are data, and the list of
data I keep is short and written down. It doubles as my list of what to back up.

The practical consequence I enjoy most is boring: when I wonder how something is set up, I grep.
I don't go digging through `/etc` trying to remember what I edited at 2 a.m. two years ago, because
there isn't anything I edited at 2 a.m. outside the repo.

## Breaking things is cheap

Every rebuild is a new generation, and the old ones stay in the boot menu. I've broken my laptop
plenty of times (graphics drivers on an NVIDIA laptop, what a surprise) and the fix was always
"reboot, pick yesterday".

The server is where this really pays off, because it's not next to me. My deploy config uses
deploy-rs, whose "magic rollback" checks it can still reach the machine after switching. If I
push a firewall change that locks me out, the server notices nobody's talking to it and rolls
itself back. I've been saved by that more than once.

## Fifty services, one person

Running that many self-hosted services alone sounds like a bad idea, and without Nix it would be.
What makes it manageable is that I almost never touch the server by hand anymore. Things mostly
move through pull requests on my own Forgejo:

Every Monday a job bumps `flake.lock` and opens a PR. Renovate does the same for container
images, which are all pinned to a digest, and merges the minor ones by itself. CI builds all
three machines on every PR, so if an update breaks the config, I find out in a red check rather
than on the server. The results land in a binary cache I host myself, so when I update my laptop
it downloads what CI already built.

None of this was set up in one go, and it has scars. The weekly lock bump updates *every* input
because I once pinned only some of them, and a nixpkgs update broke sops-nix in a way that took
me an evening to understand. The CI keeps its build results per branch because a run on one
branch used to throw away another branch's builds. Every comment in those workflow files is
something that bit me.

## Secrets in the repo (encrypted, relax)

Passwords and API keys sit in the same repo, encrypted with sops-nix. Each machine can decrypt
them with its own SSH host key, and only gets the ones its config asks for. Setting up a new
machine doesn't involve copying a `.env` file from somewhere and hoping it's the right one.

## The annoying parts

I'd be lying if I said it was all great. Nix the language is strange, the documentation is spread
across the manual, the wiki, Discourse threads and other people's configs, and some error messages
are just a wall of stack trace. Anything that ships as a prebuilt binary expecting a normal
`/usr/lib` is a fight; I have `nix-ld` enabled on the laptop for exactly that and still lose time
to it now and then.

And it's easy to over-engineer. My config is a few thousand lines of Nix for three computers.
Some of that is because I enjoy it, which is fine, but it's not the right trade for everyone.

For me, though, I don't really see myself going back. I can rebuild any of these machines from
scratch, undo pretty much any change, and I always know what's running where.
